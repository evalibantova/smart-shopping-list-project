## Future Feature Backlog (captured during design)- **Week templates:** save and reapply named week plans- **Copy last week:** one-click duplicate of previous week's plan- **Barcode scanner:** scan a product barcode (via device camera) to add or update pantry items — name, unit, and category auto-filled from Open Food Facts or a similar open product database. Primary input method for fast pantry entry; without it, maintaining a large pantry requires too much manual typing to be sustainable long-term.
- **Receipt scanner:** photograph a grocery receipt to auto-populate pantry stock- **"Cook now" suggestions:** list recipes that can be made from current pantry contents- **Expiry date tracking:** add best-before dates to pantry items- **Full shopping list editor:** rename, reorder, regroup items before shopping- **Nutritional data:** integrate kaloricketabluky.sk or similar API for per-ingredient macro/calorie data- **Import recipe from URL:** paste a link to a recipe page (e.g. food blog, allrecipes) → app scrapes/parses title, ingredients, servings, and instructions and pre-fills the recipe form for review before saving## AI Chatbot (v1 Feature)A natural-language assistant embedded in the app for hands-free updates.**Architecture:** LLM function calling — the model calls predefined tools rather than returning freeform text the app must parse. This is the guardrail: the LLM can only trigger permitted operations.**Permitted tools (write):**- `update_pantry(ingredient, quantity, unit, operation: set|add|subtract)`- `add_recipe(name, servings, ingredients[], notes)`- `modify_shopping_list(action: add|remove|check, items[])`- `plan_meal(day, slot, recipe_id)`**Permitted tools (read):**- `get_pantry()` — what's in stock- `get_cookable_recipes()` — what can I make now- `get_shopping_list()` — current list**Provider:** Provider-agnostic — user supplies their own API key (Gemini, Claude, OpenAI, etc.). App sends requests to the selected provider's function-calling endpoint.**Why deferred:** The data model needs to be stable before the chatbot can reliably operate on it. Build MVP CRUD first, then layer the assistant on top.
