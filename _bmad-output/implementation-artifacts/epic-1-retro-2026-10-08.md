## Findings

### Aggregate Views

#### Architecture Delta

**F1 — Cross-feature import: `recipes` → `meal-planner` (Medium)**
`code/src/features/recipes/index.tsx:8-9` imports `AddToWeekModal` and calendar utilities directly from `code/src/features/meal-planner/`. This introduces a hard dependency from the recipes feature into the meal-planner feature before Epic 2 was implemented. The feature-sliced architecture (`src/features/{name}/`) was established precisely to prevent this pattern; this import creates a coupling the architecture explicitly forbids and sets a precedent.

*Source:* `features/recipes/index.tsx:8-9` (code-analysis agent, verified)
*Disposition:* **Fix now** — see Action Item A1

#### Duplication Map

**F2 — `readAll()` localStorage boilerplate duplicated 4× (Low)**
`recipeService.ts:5-14`, `tagService.ts:5-13`, `ingredientsDbService.ts:7-15`, and `mealPlanService.ts` (Epic 2) each implement an identical `localStorage.getItem → JSON.parse → Array.isArray → return []` pattern. No shared helper exists.

*Source:* code-analysis agent (each file cited)
*Disposition:* **Defer** — low impact, easy to extract when a fifth service is added; not worth a dedicated story now

#### God-Class Growth

**F3 — `AddEditRecipeModal.tsx` carries 4–5 concerns (Low-Medium)**

The file is at its ceiling; adding cook-now or pantry-availability UI here in later epics would make it unmanageable. Natural extraction targets: tag sub-form (lines 259–320) and ingredient row manager (lines 323–393).

*Source:* `AddEditRecipeModal.tsx:1-418`, story-1.3 spec `warnings: [multiple-goals, oversized]`
*Disposition:* **Defer** — extract as the story naturally grows in a later epic; not worth rewiring now

#### Adversarial / Blind Hunter

**F4 — Escape handler clears input unconditionally; missing `stopPropagation` (Medium)**
`IngredientAutocomplete.tsx` attaches a document-level `keydown` handler that calls `onChange('')` on every Escape event, even when no dropdown is open. This silently erases user input in an idle ingredient row. The handler also lacks `e.stopPropagation()`, so pressing Escape while the autocomplete is focused inside a `Modal` closes both the dropdown and the modal simultaneously.

Additionally, `IngredientAutocomplete.test.tsx` test (f) ("Escape closes dropdown") asserts that `onSelect` was not called but does not assert that `onChange` was called with `''` — while test (g) (mousedown-outside) does assert it. The Escape-specific `onChange` call is untested.

*Source:* `IngredientAutocomplete.tsx` (Escape handler); `IngredientAutocomplete.test.tsx` test (f) vs (g) — VG layer pre-verified
*Disposition:* **Fix now** — see Action Item A2

**F6 — `key={idx}` on ingredient rows (Medium)**
`AddEditRecipeModal.tsx:~1992` uses the array index as the React key for ingredient rows. Removing a row from a non-tail position causes React to reuse keys incorrectly, shifting input values and corrupting the form state for the user mid-edit.

*Source:* `AddEditRecipeModal.tsx:~1992` (blind-hunter, verified — ingredient list uses map with `idx`)
*Disposition:* **Fix now** — see Action Item A3

**F7 — "Add to Week" button inaccessible when disabled (Medium)**
`RecipeDetail.tsx:~90-95`: the "Add to Week" button in the `recipes` context uses `opacity: 0.35` and `onClick={undefined}` to appear disabled, but has neither a `disabled` attribute nor `aria-disabled="true"`. Keyboard users can tab to it; screen readers have no signal it is inert.

*Source:* `RecipeDetail.tsx:~90-95` (blind-hunter + code-analysis, verified)
*Disposition:* **Fix now** — see Action Item A4

**F8 — Mobile detail overlay not hidden from screen readers (Medium)**
`RecipesPage/index.tsx` (overlay section): the mobile detail overlay slides off-screen via `translateX(100%)` when closed but remains fully rendered in the DOM with no `aria-hidden`. Screen readers can traverse and announce its content even when invisible.

*Source:* `features/recipes/index.tsx` (overlay section) (blind-hunter, verified)
*Disposition:* **Fix now** — see Action Item A5

**F12 — Modal lacks `role="dialog"`, `aria-modal`, focus trap (Medium)**
`Modal.tsx` renders no `role`, `aria-modal`, `aria-labelledby`, or focus trap. Already tracked in story-1.3's deferred list at `severity: medium`.

*Source:* `Modal.tsx:72-131`; `spec-1-3-recipe-management.md` deferred section
*Disposition:* **Defer** — already tracked; no new action item needed

#### Verification Gap

**F5 — `recipesFilter.test.ts` tests local copies of `filterRecipes` and `scaleQty` (Medium)**
The file defines its own `filterRecipes` (lines 443–451) and `scaleQty` (lines 456–459) with a comment saying they were "extracted from" the source files — but no import statement exists. Changes to the actual filter or scale logic in `features/recipes/index.tsx` or `RecipeDetail.tsx` pass the test suite undetected. Test (g) for mousedown-outside confirmed the pattern `expect(onChange).toHaveBeenCalledWith('')` was known and available (applied) but omitted for Escape. Additionally, `scaleQty` in the test lacks the `base > 0` guard that the production path has, so the test utility returns `Infinity` for 0-servings inputs while production returns 1.

*Source:* `__tests__/recipesFilter.test.ts:443–459` — VG layer pre-verified (reads test file, confirms no import)
*Disposition:* **Fix now** — see Action Item A6

**F11 — `removeRecipe` selectedId reset is untested (Low)**
`recipesSlice.ts` atomically clears `selectedId` when the deleted id matches, but `recipesSlice.test.ts` contains only two tests covering `initRecipes` — no test calls `removeRecipe`, `addRecipe`, `updateRecipe`, `addTag`, or `selectRecipe`. The selectedId-reset behavior is fully unpinned.

*Source:* `__tests__/recipesSlice.test.ts` — VG layer pre-verified
*Disposition:* **Fix now** — see Action Item A6 (bundled with test improvements)

#### Acceptance Auditor

**F9 — Servings count missing from recipe list rows (Medium — spec violation)**
Story 1.3 AC specifies each row shows "emoji, name (truncated with ellipsis if too long), **servings count**, and color-coded flat tag chips." The actual implementation in `features/recipes/index.tsx:~2260–2283` renders emoji, name, and tags — no servings count. This is an unambiguous AC omission.

*Source:* `features/recipes/index.tsx:~2260–2283` vs story-1.3 AC row spec
*Disposition:* **Fix now** — see Action Item A1 (bundled with other recipe-list fixes)

**F10 — Modal backdrop hardcoded `rgba(0,0,0,0.4)` (Low)**
`Modal.tsx` backdrop uses a hardcoded rgba value. The constraint is "All color, shadow, typography, and radius values must be CSS custom properties." The mobile `border-radius: '16px 16px 0 0'` is similarly hardcoded.

*Source:* `components/ui/Modal.tsx` (backdrop + border-radius)
*Disposition:* **Fix now** — see Action Item A5 (bundled with modal fixes)
